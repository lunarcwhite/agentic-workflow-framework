Agent Engineering Pitfalls

The 5 Common Pitfalls of Autonomous AI Coding

How unregulated AI models fail in real repositories — and how structured task contracts, evidence receipts, and CLI validation resolve each failure mode.

Pitfall 01

The Phantom Pass

Unbounded AI Behavior

The model politely announces: "I ran pytest and all 42 tests passed with zero errors!" In reality, the test command was never executed, exit codes were unverified, or assertions were commented out.

UAAF Evidence Receipt

Rejects conversational claims. Task sign-off requires an immutable evidence-receipt.yaml capturing command argv, exit code 0, test stdout/stderr, and output SHA-256 hash verified by uaf check.

Pitfall 02

The Lazy Stub (// TODO Syndrome)

Unbounded AI Behavior

When encountering complex edge cases, the agent writes // TODO: implement error handling later or returns mock placeholder values and prematurely claims the user story is fully delivered.

UAAF Definition of Done

Tasks must satisfy explicit acceptance criteria declared in task-contract.yaml. Changes are evaluated against concrete contract requirements before a deliverable can be marked complete.

Pitfall 03

Silent Scope Creep

Unbounded AI Behavior

Asked to adjust a CSS padding or fix a simple typo, the agent refactors the entire design system, alters ESLint configurations, downgrades packages, and mutates dozens of unauthorized files.

UAAF Task Contract Scope

Work is bounded by task-contract.yaml declaring explicit permitted_files. Git changes are tracked via uaf git trace and validated against the contract so unauthorized diffs are flagged immediately.

Pitfall 04

Long-Horizon Context Amnesia

Unbounded AI Behavior

Over long multi-turn conversations, chat tokens degrade. The model forgets decisions made earlier, contradicts project architecture, and re-introduces previously solved bugs.

UAAF Structured Memory & Handoff

Persists validated architectural decisions and progress into .ai/memory/STATE.md. Uses uaf memory to generate clean session handoffs so new agent sessions resume with verified context.

Pitfall 05

Framework Fantasy & Over-Abstraction

Unbounded AI Behavior

The agent invents multiple unnecessary layers of abstract factory classes, adds speculative utilities, or introduces external third-party dependencies that were never requested.

UAAF Purpose Gate

Axiom 4 mandates: Reuse → extend → modify → create. Introducing new abstractions or packages requires explicit architectural justification in the task contract.

Repository Governance

The Three Governance Gates

Formal architectural policies defined in .ai/anti-slop/GATES.md that guide both agent instructions and human / CI verification before merge.

NON-NEGOTIABLE

HARD GATE

Fundamental project invariants. Deliverables violating these criteria are rejected during review and verification.

  • Fabrication & Hallucinated APIs
  • Fake Verification (Unrecorded Test Passes)
  • Silent Scope Expansion (Unpermitted Files)
  • Intent Replacement or Goal Drift
  • Known Incompleteness Claimed as Done
  • Secret & Credential Leakage
JUSTIFICATION

PURPOSE GATE

Prevents speculative extensibility and unnecessary architectural bloat. Divergence requires concrete rationale.

  • Unsolicited Architectural Abstractions
  • External Dependency Introductions
  • Unsolicited Major File Refactoring
  • Decorative Motion & Cosmetic Fluff
  • Pattern Divergence from Existing Code
  • Speculative Extensibility Layers
DURABILITY

QUALITY LOCK

Maintains repository standards, existing test suite health, and consistency across multi-turn agent handoffs.

  • Repository Naming & Token Consistency
  • Component Reuse over Ad-hoc Code
  • Test Suite Pass & Zero Regression Requirement
  • WCAG AA+ Accessibility & Contrast
  • Clean Error Handling & Typing
  • Durable State Compaction Persistence
Kernel Invariants

The 10 Golden Rules of Agentic Engineering

Embedded inside AGENTS.md to guide coding assistants (Claude Code, Cursor, Antigravity, Copilot) before any consequential change.

01

Understand before changing.

Read manifests, architecture records, and established state before touching production lines.

02

Inspect before inventing.

Audit existing modules and utilities before writing new helper functions or synthetic wrappers.

03

Search before creating.

Grep and semantically index the codebase to reuse existing conventions and design tokens.

04

Reuse → extend → modify → create.

The strict priority cascade. Creating new code is the last resort when extension is impossible.

05

Preserve user intent.

Never replace the user's underlying goal with an easier sub-goal or simplified approximation.

06

Never silently expand scope.

Edits are restricted strictly to files declared in the leased task contract perimeter.

07

Treat memory as hypothesis.

Past claims and conversation memories are unverified until proven against active disk state.

08

Evidence before completion.

No task can be declared done without a verifiable, reproducible evidence receipt.

09

Keep changes minimal & complete.

Surgical precision. Zero leftover scaffolding, zero partial stubs, and zero formatting churn.

10

Persist durable handoffs.

Compress session trajectory into durable state so the next agent turn resumes seamlessly.

Deterministic Workflow

The Bounded Execution Lifecycle

How UAAF guides an agent from instruction to verifiable delivery with transparent governance.

STEP 01

Task Contract

Explicit intent, non-goals, permitted files, and test criteria declared in task-contract.yaml.

STEP 02

Kernel Invariants

Agent works bounded by 10 Golden Axioms in AGENTS.md: Understand > Inspect > Search > Reuse > Minimal Edits.

STEP 03

Governance Gates

Hard, Purpose, and Quality gates evaluate proposed changes against repo standards and contract limits.

STEP 04

Evidence Receipts

Test outputs, exit codes, and SHA-256 hashes anchored into evidence-receipt.yaml and validated via uaf check.

STEP 05

Durable Handoff

Memory compactor (uaf memory) persists validated decisions into .ai/memory/STATE.md for clean turn continuity.

Developer Setup

Start Bounding Your Agents in 60 Seconds

Use the Python CLI for automated verification or drop UAAF directly into any repository as a pure prompt-and-governance scaffold.

# 1. Clone repository & install CLI globally in editable mode
git clone https://github.com/lunarcwhite/agentic-workflow-framework.git
cd agentic-workflow-framework
pip install -e .

# 2. Initialize UAAF governance scaffold in your project
uaf init ./my-project --profile standard

# 3. Check health and run automated contract verification
uaf doctor ./my-project
uaf check ./my-project
# 1. Initialize project with Team Orchestrator & Plugin Marketplace (v3.2.0)
uaf init ./my-project --profile full --extension v3.2.0

# 2. Automatically decompose goal across 6 team patterns (e.g. fan_out_fan_in)
python tools/uaf.py team compose "Build distributed payment dashboard" --pattern fan_out_fan_in

# 3. Lock disjoint file perimeters atomically via .claims.lock
python tools/uaf.py team lock --agent claude-code --lease 900

# 4. Export native configs to Claude Code, Antigravity, Cursor, and Pi
python tools/uaf.py team export --target all

# 5. Check status, release locks, and verify deliverables
python tools/uaf.py team status
python tools/uaf.py team release
python tools/uaf.py team verify
# Works for TypeScript, Go, Rust, Java, C#, PHP, or any codebase!
# 1. Copy the knowledge scaffold and agent kernel into your project root:
cp -r scaffold/.ai/ ./my-project/.ai/
