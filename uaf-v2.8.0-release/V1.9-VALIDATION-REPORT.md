# UAAF v1.9 Validation Report

## Scope

UAAF v1.9 adds Trust Anchoring & Cryptographic Integrity on top of the cumulative UAAF v1.0-v1.8 stack.

## Release qualification

The v1.9 test module contains **12/12 test cases**. Each case was executed as a fresh subprocess because the UAAF suite is subprocess-heavy. The cases cover initializer/conformance, Full-profile enforcement, legacy compatibility, key generation, trust initialization, signing/verification, payload tamper detection, signed bundle requirements, audit-chain tamper detection, root pinning and rotation, private-key rejection, fail-closed authorization, strict signed-bundle conformance, and mandatory external-pin behavior.

The v1.9 scenarios were completed as isolated process runs with successful exit status. A few file-level pytest runs have historically hit the outer execution harness timeout after child assertions completed; those timeouts are not used as release-pass signals.

## Regression smoke

- Core tooling: **12/12 passed**.
- v1.1 compatibility smoke: **2/2 passed**.
- v1.8 compatibility smoke: **3/3 passed**.
- Northstar v1.9 strict conformance: **PASS**.

The previously released v1.0-v1.8 suites remain the historical qualification baseline for their respective releases; this report does not relabel those historical runs as a fresh cumulative 1.9 run.

## Cryptographic scenarios

1. Detached Ed25519 signing and verification.
2. Exact payload-hash mismatch detection after tampering.
3. Distinct signature purposes: `trust-root`, `trust-keys`, `trust-policy`, `delegations`.
4. Required signed-bundle verification.
5. External root fingerprint pinning.
6. Fail-closed behavior when an external pin is required but omitted.
7. Root rotation evidence signed by the old root.
8. Hash-chain audit validation and tamper detection.
9. Private-key rejection by conformance.
10. Root policy signature invalidation when the policy changes.
11. Strict Full-profile conformance with cryptography required.
12. Legacy v1.8 trust audit preservation during v1.9 migration.

## Reference project

Northstar v1.9 uses public trust material and detached signatures only. No private signing key is stored in the project. Its root policy requires cryptographic integrity and declares all four required signature purposes.

## Safety properties

- Private signing keys stay outside the repository and are rejected when placed in `.ai/trust`.
- Required cryptographic verification fails closed.
- Required external root pins fail closed when missing or mismatched.
- Root policy changes invalidate the old root signature until the policy is re-signed.
- Audit-chain tampering is detectable.
- Signature purpose mismatches are rejected.
- Root rotation is explicit and signed by the previous root.

## Backward compatibility

v1.0-v1.8 project semantics remain unchanged. v1.9 is Full-profile and opt-in. Initializing with an older extension does not emit the v1.9 trust namespace.
