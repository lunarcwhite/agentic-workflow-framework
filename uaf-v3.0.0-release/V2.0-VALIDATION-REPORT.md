# UAAF v2.0 Validation Report

## Scope

Validation covers distributed federation identity, signed handoffs, replay protection, peer pinning, deny-by-default policy, vector-clock state merge, explicit conflict handling, v2.0 initializer/doctor/conformance integration, and backward-compatibility smoke tests for shared tooling.

## v2.0 extension tests

```text

```

The subprocess-heavy file-level runner is intentionally not used as the acceptance metric because the execution harness can hang when many cryptographic subprocesses are launched inside one pytest process. Each v2.0 scenario was therefore executed in a fresh process and recorded by exit code.

## Security properties validated

- private federation and signing keys are never packaged;
- remote identity tampering fails closed;
- audience mismatch fails closed;
- replayed envelopes are rejected;
- expired envelopes are rejected;
- unallowlisted federation actions are denied;
- concurrent different state values become explicit unresolved conflicts;
- transport remains external to the federation semantics;
- no network socket is opened by the reference federation implementation.

## Release acceptance

The release archive is re-extracted before publication. The archive must contain no Python bytecode, pytest cache, private key, or example `.git` metadata.
