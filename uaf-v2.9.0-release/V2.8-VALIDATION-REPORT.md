# UAAF v2.8 Validation Report

## Result

The v2.8 custody extension was validated using fresh-process provider tests plus targeted downgrade and doctor checks.

## Verified

- v2.8 initializer creates custody artifacts.
- v2.8 manifest and federation key-storage protocol are correct.
- Filesystem provider reports PASS.
- Inventory exposes metadata only and never private key material.
- Key registration is metadata-only.
- Unavailable KMS/HSM providers remain inactive and do not trigger filesystem fallback.
- Configured external adapter health can make a provider available.
- Provider switch refreshes health state.
- `secret_export` and `private_key_return` remain disabled.
- Explicit v2.8 → v2.7 downgrade removes only v2.8 custody artifacts.
- Doctor uses compact v2.8 diagnostics.
- Conformance recognizes `CONF-V28-*` rules.

## Test accounting

- v2.8 dedicated tests: 6 passed under pytest; doctor was validated as a separate deterministic smoke because the historical subprocess-heavy suite can stall in this environment.
- Doctor smoke: PASS.
- v2.7 impacted lifecycle path: PASS.

## Limitations

The reference build does not contain vendor-specific AWS/Azure/GCP KMS or HSM integrations. Those remain adapter contracts. No private key is included in the repository or release archive.
