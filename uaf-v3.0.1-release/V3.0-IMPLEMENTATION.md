## Architecture choices

### Contract first

The task contract is the source of truth for remote execution authority. Runtime state never replaces the signed contract.

### Lease as an execution boundary

The lease contains its own contract hash, owner, timestamps, grant amount, renewable flag, and lifecycle status. All stateful transitions mutate the exact document instance that is persisted, preventing lost updates from read-again/save-again patterns.

### Evidence as a mandatory result component

The default policy requires at least one evidence artifact. Artifacts are hashed at the executor and recorded in a remote-attested evidence receipt.

### Independent verification without over-claiming

The origin hashes locally available artifacts. Non-local artifacts remain marked `NOT_LOCAL` and the overall result is reported as metadata-only verification rather than pretending the artifact was independently inspected.

### Provider-backed signing

The v3 runtime delegates signing to v2.9 provider-backed key operations. Private key material is not kept in project runtime files. Runtime signing purposes are explicit.

### Terminal state protection

`CANCELLED`, `EXPIRED`, `COMPLETED`, and `RESULT_SUBMITTED` are terminal. Late cancellation is rejected instead of overwriting terminal state.

### Peer ceiling enforcement

Delegated actions and risk are constrained by the trusted peer metadata in addition to the local route. A route cannot grant a peer more authority than the peer's trusted federation record permits.

## Deliberate non-goals

- no automatic network transport
- no hidden authority transfer
- no automatic task retry with a new contract
- no semantic auto-resolution of conflicting intent
- no private-key export API
- no claim that metadata-only evidence equals independent artifact verification

## Operational sequence

```text
route → delegate → transfer contract → accept → start → execute → complete → transfer result/lease receipt → verify-result → deliver
```

Cancellation uses:

```text
cancel → transfer cancellation → apply-cancel
```

Lease maintenance uses:

```text
renew | sweep
```

## Audit surfaces

`.ai/federation/runtime/PROVENANCE.jsonl` is the runtime provenance chain.

`.ai/federation/runtime/AUDIT.jsonl` records security-relevant runtime events.

`.ai/federation/runtime/EVIDENCE/` contains evidence receipts.

`.ai/federation/runtime/LEASE-RECEIPTS/` contains signed lease grants.

## Backward compatibility

The v2.9 provider-backed key layer remains the signing substrate. The v3 initializer reuses v2.9 setup and appends the runtime layer. Existing v2.9 functionality is not semantically redefined by v3.
