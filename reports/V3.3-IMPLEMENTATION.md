# UAAF v3.3 Implementation Report: Native Landing Page Design & SEO Governance

## 1. Overview & Objective

UAAF v3.3 introduces **Native Landing Page Design Architecture** and **Automated Technical SEO & AEO Governance** (Protocol `UAAF-SEO-1.0`). 

While external prompt repositories provide fragmented guidance, UAAF v3.3 elevates landing page engineering and search discoverability into **governed, deterministic, and verifiable systems**:
1. Establishing the **2-Part Native Landing Page Framework** inspired by proven conversion methodologies (Part A Strategy & Structure + Part B Non-negotiable Visual System).
2. Implementing the **`uaf seo` CLI module**, providing automated quality gates for HTML metadata, OpenGraph, Twitter Cards, canonical tags, single `<h1>` hierarchy, image accessibility, and Schema.org JSON-LD structured data.
3. Enabling automatic multi-agent promotion of **`landing_page_pro`** and **`seo_specialist`** inside `uaf team compose`.
4. Delivering the **`landing-page-seo`** package pre-bundled within UAAF's catalog, ready for instant offline scaffolding and multi-target export to Claude Code (`.claude/`), Antigravity (`.agents/`), Cursor (`.cursor/`), and Pi (`.pi/`).

## 2. Core Deliverables

### A. Native SEO & Landing Page Utility (`tools/uaf_seo.py`)
Registered under `uaf seo`:
- `uaf seo audit <path> [--threshold 80]`: Evaluates HTML files against 8 quality checks (title, description, viewport, canonical, OpenGraph, heading hierarchy, image `alt` attributes, and Schema.org JSON-LD blocks).
- `uaf seo generate --type {SoftwareApplication,Organization,WebSite,FAQPage} --name <name> --description <desc> --url <url>`: Generates standards-compliant Schema.org JSON-LD.

### B. Curated Native Package (`landing-page-seo` in `tools/uaf_plugin.py`)
- Shipped with two high-fidelity skill playbooks:
  - `landing-page-design`: Part A Strategy (intake discovery, 12-section conversion hierarchy, PAS/AIDA copywriting, build order) and Part B Visual System (Geist/Manrope typography, balanced text-wrap, non-arbitrary spacing tokens, flat cards with full perimeter borders).
  - `technical-seo`: Technical SEO standards, OpenGraph cards, Schema.org JSON-LD structured data, AEO question-answer formatting, and automated verification with `uaf seo audit`.

### C. Dynamic Team Orchestrator Adaptation (`tools/uaf_team.py`)
- Added `landing_page_pro` and `seo_specialist` to `ROLE_DEFINITIONS`.
- Keyword routing in `decompose_tasks` elevates frontend roles to `landing_page_pro` when prompts mention landing pages, marketing, or conversion.
- Allocates disjoint file perimeters strictly to `docs/*` and `src/components/*` backed by `.claims.lock`.

### D. Scaffolding & Conformance Validation (`tools/uaf_init.py` & `tools/uaf_check.py`)
- Supported `--extension v3.3` and `--extension v3.3.0` in `uaf_init.py`.
- Added `validate_v33_extensions` in `uaf_check.py` validating protocol `UAAF-SEO-1.0`, extension section presence, and minimum audit score bounds (`CONF-V33-001` through `CONF-V33-003`).

### E. Normative Specification (`spec/UAAF-v3.3-EXTENSIONS.md`)
Established the normative specification for Protocol `UAAF-SEO-1.0`.

## 3. Invariants & Security Boundaries
- **Disjoint Perimeter Rule**: Landing page and SEO specialists remain bound to non-overlapping file perimeters guarded by `.claims.lock`.
- **Zero Mock / Anti-Slop Gate**: Copywriting must contain specific outcomes without vague filler words, with zero empty placeholders or unverified claims.
- **Audit Verification Gate**: Web surfaces must pass `uaf seo audit` before declaring task completion.
