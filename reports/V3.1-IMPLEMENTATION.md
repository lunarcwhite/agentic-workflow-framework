# UAAF v3.1 Implementation Report: Team-Architecture Factory & Multi-Agent Orchestrator

## 1. Overview & Objective

UAAF v3.1 introduces native multi-agent coordination capabilities inspired by the Team-Architecture Factory paradigms in modern agent harnesses (such as `pi-agent-harness` and `revfactory/harness`).

Instead of introducing heavyweight direct LLM API wrappers or bloated client libraries, UAAF v3.1 acts as the **architectural governor and coordinator**:
1. Decomposing high-level objectives into **bounded, non-overlapping task contracts**.
2. Enforcing **atomic file locking** through `.claims.lock` to prevent merge conflicts and race conditions.
3. Providing **native multi-target export** for Claude Code (`.claude/agents/*.md`), Google Antigravity (`.agents/skills/team-*/SKILL.md`), Cursor (`.cursor/rules/team.mdc`), and Pi (`.pi/agents/*.md`, `.pi/prompts/*.md`).
4. Verifying deliverables against task contracts and evidence receipts.

## 2. Core Deliverables

### A. Team Architecture Engine (`tools/uaf_team.py`)
Provides six architectural patterns:
1. **Pipeline (`pipeline`)**: Sequential feed-forward execution (`architect` → `engineer` → `reviewer` → `verifier`).
2. **Producer-Reviewer (`producer_reviewer`)**: Paired iterative implementation and critique loop with evidence gating (`producer`, `reviewer`).
3. **Fan-Out / Fan-In (`fan_out_fan_in`)**: Orthogonal parallel decomposition with disjoint permitted files followed by integrated assembly (`coordinator`, `backend_specialist`, `frontend_specialist`, `integrator`).
4. **Expert Pool (`expert_pool`)**: Domain-specific dispatch routed by subsystem (`planner`, `domain_expert`, `security_auditor`, `qa_engineer`).
5. **Supervisor (`supervisor`)**: Hierarchical delegation and lease supervision (`supervisor`, `worker_primary`, `worker_secondary`).
6. **Hierarchical Swarm (`hierarchical`)**: Enterprise multi-tier governance (`lead_architect`, `system_engineer`, `qa_lead`, `compliance_officer`).

### B. CLI Integration (`tools/uaf.py`)
Registered the `team` command in the top-level CLI:
- `uaf team compose <prompt> [--pattern <pat>]`
- `uaf team lock [<task_id>] [--agent <agent_id>] [--lease <sec>]`
- `uaf team release [<task_id>] [--agent <agent_id>]`
- `uaf team export [--target {claude-code,antigravity,cursor,pi,all}]`
- `uaf team status`
- `uaf team verify`

### C. Extension & Conformance Checks (`tools/uaf_check.py` & `tools/uaf_init.py`)
- Supported `--extension v3.1` and `--extension v3.1.0` in `uaf_init.py`.
- Implemented `validate_v31_extensions` validating protocol `UAAF-TEAM-1.0`, team configuration schema, and the Disjoint Perimeter Invariant (`CONF-V31-001` through `CONF-V31-006`).
- Integrated task contracts with UAAF v1.0 standard schema (`TASK-0001` format with `constraints`, `non_goals`, `verification`, and SHA-256 integrity hashes).

### D. Multi-Target Exporters
- **Claude Code**: Creates `.claude/agents/{role}.md` subagent declarations with permitted file scopes.
- **Antigravity**: Creates `.agents/skills/team-{pattern}/SKILL.md` (team orchestrator) and `.agents/skills/team-{role}/SKILL.md` (role persona skills).
- **Cursor**: Creates `.cursor/rules/team.mdc` defining active team boundaries and rules.
- **Pi / pi-agent-harness**: Creates `.pi/agents/{role}.md` and `.pi/prompts/team-{pattern}.md`.

## 3. Invariants & Security Boundaries
- **Disjoint Perimeter Rule**: $\text{permitted\_files}(A) \cap \text{permitted\_files}(B) = \emptyset$ ensures no two agents edit the same file simultaneously.
- **Atomic Lease Locking**: Backed by `.ai/agents/CLAIMS.yaml` and `.claims.lock`.
- **Zero Mock / Zero Slop Gate**: Deliverables require exit code 0 evidence receipts and hash verification.
