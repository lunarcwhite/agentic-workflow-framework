# UAAF v3.2 Implementation Report: Agentic Plugin Marketplace & Domain Specialists

## 1. Overview & Objective

UAAF v3.2 introduces the **Agentic Plugin Marketplace Manager** (Protocol `UAAF-PLUGIN-1.0`), establishing native interoperability with large-scale agentic plugin and skill ecosystems (specifically modeled after and compatible with `wshobson/agents`).

While external agent repositories provide hundreds of specialized prompts, personas, and skills, they often lack formal execution governance, concurrency boundaries, anti-slop guarantees, and cryptographic verification. UAAF v3.2 bridges this gap by acting as the **governing control plane and runtime coordinator**:
1. Enabling developers to search, download, and scaffold specialized plugins into `.ai/plugins/<name>/`.
2. Automatically injecting UAAF Golden Axioms (`GOVERNANCE.md`) and anchoring cryptographic evidence receipts (`.ai/evidence/EV-PLUGIN-*.yaml`).
3. Dynamically discovering installed plugin personas in `uaf team compose` without manual configuration.
4. Intelligently elevating generic team roles to domain specialists (such as `fastapi_pro`, `react_pro`, `postgresql_dba`, `devops_engineer`, and `testing_specialist`) based on task intent and attaching required skills to task contracts.
5. Providing multi-target export to Claude Code (`.claude/`), Antigravity (`.agents/`), Cursor (`.cursor/`), and Pi (`.pi/`).

## 2. Core Deliverables

### A. Plugin Marketplace Manager (`tools/uaf_plugin.py`)
Provides CLI subcommands registered under `uaf plugin`:
- `uaf plugin list [--remote]`: Displays installed plugins and available marketplace catalog packages.
- `uaf plugin search <query>`: Fast search across plugin names, descriptions, agents, skills, and slash commands.
- `uaf plugin install <name> [--force]`: Fetches live plugin manifests from GitHub `wshobson/agents` with instant offline curated fallback. Scaffolds `plugin.json`, `agents/`, `skills/`, and `commands/`.
- `uaf plugin govern <name>`: Injects `GOVERNANCE.md` (mandating Golden Rules, disjoint perimeters, bounded tool execution, zero mock stubs) and anchors a verified evidence receipt.
- `uaf plugin export <name> [--target {all,claude-code,antigravity,cursor,pi}]`: Projects installed plugin personas and skills directly into native IDE harnesses.

### B. Dynamic Role Discovery & Domain Adaptation (`tools/uaf_team.py`)
- Added `discover_installed_roles(root: Path)`: Automatically scans `.ai/plugins/` to register custom agents and skills into the active team roster.
- Added specialized domain roles to `ROLE_DEFINITIONS`:
  - `fastapi_pro`: High-performance async APIs, Pydantic v2 schemas, OpenAPI specs.
  - `django_pro`: Scalable backends, Django ORM, REST Framework, secure auth.
  - `react_pro`: React components, custom hooks, state machines, memoization.
  - `nextjs_pro`: Next.js App Router, Server Actions, SSR optimization.
  - `vue_pro`: Vue 3 composition, Pinia state, Vite tooling.
  - `postgresql_dba`: Query plan optimization, index strategies, non-locking schema migrations.
  - `devops_engineer`: Docker multi-stage builds, GitHub Actions CI/CD, K8s manifests, Terraform.
  - `testing_specialist`: Pytest fixtures, mock isolation, edge case fuzzing, coverage gates.
- Enhanced `decompose_tasks`: Automatically maps generic roles to domain specialists when task prompts contain domain keywords, and binds `required_skills` into `.ai/tasks/active/TASK-*.yaml`.

### C. Extension & Conformance Checks (`tools/uaf_init.py` & `tools/uaf_check.py`)
- Supported `--extension v3.2` and `--extension v3.2.0` in `uaf_init.py`.
- Added `validate_v32_extensions` in `uaf_check.py` checking protocol `UAAF-PLUGIN-1.0`, extension section presence, and mandatory `GOVERNANCE.md` audit compliance (`CONF-V32-001` through `CONF-V32-003`).

### D. Normative Specification (`spec/UAAF-v3.2-EXTENSIONS.md`)
Established the normative specification for Protocol `UAAF-PLUGIN-1.0`, defining subsystem capabilities, governance mandates, and conformance assertions.

## 3. Invariants & Security Boundaries
- **Governance Mandate Invariant**: Every installed plugin must have an audit record and valid `GOVERNANCE.md`.
- **Disjoint Perimeter Rule**: Domain specialists remain bound to strictly non-overlapping file perimeters guarded by `.claims.lock`.
- **Zero Mock / Zero Slop Gate**: Specialist code generation must satisfy acceptance criteria with exit code 0 test receipts.
