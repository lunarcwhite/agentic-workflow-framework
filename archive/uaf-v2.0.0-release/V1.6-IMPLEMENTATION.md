- doctor integration

- delivery-gate outcome analysis
- safety defaults preventing automatic policy/intent/memory mutation

## Design choice

The optimizer deliberately does not contain an `apply` operation. v1.6 produces proposals and evidence only. This preserves the distinction between learning from telemetry and changing project policy.

## Safety

The optimizer reads metadata-first telemetry. It does not copy prompt or source contents into its own proposal artifacts.

## Verification behavior

Recommendations are derived from observed telemetry and stored with evidence metadata. The implementation has no automatic policy-apply, intent-rewrite, or memory-delete path.
