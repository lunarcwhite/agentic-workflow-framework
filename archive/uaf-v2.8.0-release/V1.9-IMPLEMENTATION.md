## CLI

```bash
python tools/uaf.py crypto keygen ./keys --key-id AGENT-ROOT-001
python tools/uaf.py crypto trust-init ./project --key-id AGENT-ROOT-001 --public-key ./keys/AGENT-ROOT-001.public.pem
python tools/uaf.py crypto sign ./project --file ./project/.ai/trust/ROOT.yaml --private-key ./keys/AGENT-ROOT-001.private.pem --key-id AGENT-ROOT-001 --purpose trust-root
python tools/uaf.py crypto verify ./project --file ./project/.ai/trust/ROOT.yaml --purpose trust-root --json
python tools/uaf.py crypto bundle-check ./project --pinned-root-fingerprint <sha256> --json
python tools/uaf.py crypto audit-check ./project --json
python tools/uaf.py crypto rotation-create ./project --old-private-key ./keys/old.private.pem --old-key-id ROOT-OLD --new-key-id ROOT-NEW --new-public-key ./keys/new.public.pem --effective-at 2030-01-01T00:00:00Z --reason scheduled --out ./project/.ai/trust/KEY-ROTATION.yaml
python tools/uaf.py crypto rotation-check ./project --file ./project/.ai/trust/KEY-ROTATION.yaml --new-public-key ./keys/new.public.pem --json
```

## Safety boundaries

- Private keys are never generated inside `.ai/trust`.
- Trust evaluation fails closed when cryptographic integrity is required and the bundle cannot be verified.
- Required external root pins fail closed when the caller omits the pin.
- Trust-root, trust-keys, trust-policy, and delegations are distinct signature purposes.
- v1.8 audit history is preserved separately rather than silently interpreted as a v1.9 hash chain.
