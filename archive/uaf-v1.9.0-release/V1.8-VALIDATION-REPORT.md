## v1.8 scenarios

1. Full-profile-only initialization.
2. Legacy v1.7 initialization does not emit v1.8 trust files.
3. Root/direct authority evaluation.
4. Bounded delegation and authorized delegatee evaluation.
5. Delegator without delegation authority is denied.
6. Risk ceiling produces REVIEW_REQUIRED.
7. Evidence floor produces REVIEW_REQUIRED.
8. Expired delegation denies access while an explicit replacement may be issued.
9. Revoked delegation denies access and writes audit metadata.
10. Unknown agent is denied.
11. Multiple delegation paths select a valid path rather than the first path.
12. Evidence history can impose a review requirement and then satisfy it with verified evidence.
13. Active delegation cycle is rejected by conformance.
14. Doctor and strict conformance recognize the v1.8 trust layer.

## Safety checks

- No secret value is emitted by the trust evaluator.
- Delegation expiry is mandatory.
- Self-delegation is rejected.
- Capability, domain, and risk escalation is rejected.
- Revoked delegations are not considered active.
- Direct authority is explicit.
- Trust is not represented as a numeric score.

## Harness note

Some UAAF pytest files are subprocess-heavy and can trigger the surrounding execution harness timeout after assertions have already completed. For release qualification, each suite was executed independently and the output/exit status was evaluated at suite level. No assertion failures remain in the v1.8 implementation.
