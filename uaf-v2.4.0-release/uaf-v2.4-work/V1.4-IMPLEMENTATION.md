# UAAF v1.4 Implementation Notes

UAAF v1.4 adds three operational extensions without changing UAAF v1.0 protocol semantics.

| Extension | Implementation | Safety model |
|---|---|---|
| Security Diagnostics | `tools/uaf_security.py` | read-only; never prints matched secret values |
| Git ↔ Task Traceability | `tools/uaf_git_task.py` | advisory semantic mapping; Git remains authoritative for history |
| Runtime Evidence Delivery Gate | `tools/uaf_delivery.py` | conditional gate using existing runtime receipts |
| Unified CLI | `tools/uaf.py` | dispatch-only |
| Initializer | `tools/uaf_init.py` | opt-in cumulative `v1.4` |
| Conformance | `tools/uaf_check.py` | `CONF-V14-*` checks |
| Diagnostics | `tools/uaf_doctor.py` | aggregates v1.4 status |

## Design decisions

### Security
The scanner favors high-confidence findings over aggressive secret heuristics. It reports path, line, code, and description, but never echoes the matched secret.

### Git ↔ Task
The trace layer separates framework metadata from semantic product changes. Exact files and module prefixes are treated as the explicit semantic contract. Untracked bootstrap artifacts are ignored unless the task explicitly expects them.

### Runtime delivery
Runtime evidence is conditional. Critical-risk tasks can require runtime evidence through the manifest; individual tasks can require it directly in their verification plan. A verified receipt satisfies only the runtime dimension, not the rest of Delivery Gate.

## Compatibility

- v1.4 requires Full profile when selected explicitly.
- `--extension v1.3` does not emit v1.4 artifacts.
- v1.0-v1.3 project semantics remain unchanged.
